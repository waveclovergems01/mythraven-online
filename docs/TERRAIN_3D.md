## Implementation

`shared/terrain-data.mjs` owns units and elevation generation; `shared/terrain-movement.mjs` owns navigation and movement. Browser adapters in `src/terrain` load the same shoreline mask; the server reads it with Sharp. Immutable navigation is cached once per terrain, with independent movement state for each player. `server/terrain-room.mjs` validates commands, coalesces bursts to one path calculation per player per tick, assigns safe separated spawns and broadcasts numbered acknowledgements. `src/network/terrain-client.ts` sends clicks immediately and owns connection lifecycle; `terrain-prediction.ts` handles local prediction, replay and reconciliation. `terrain-mesh.ts` and `novice-player.ts` create render objects. `TerrainWorld.ts` owns raycasts, nameplates, render interpolation and cleanup; `orbit-camera.ts` handles safe camera placement, `daylight.ts` sky/lighting/shadows, and `environment-settings.ts` their settings UI. The world's read-only snapshot supports tests.

This is the shared-world foundation for further MMO systems, not a claim of massive-scale readiness. Display names are cosmetic and do not authenticate account ownership. Persistent characters, account-to-game authorization, inventory/combat, reconnect resume, cross-zone travel, distributed hosting, and sustained load testing remain future work. No database, deployment or new cloud service is introduced.
